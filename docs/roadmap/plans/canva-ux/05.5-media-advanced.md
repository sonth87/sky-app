# GĐ14.5 — Advanced Media Management (sau GĐ14 basic)

## Bối cảnh

GĐ14 xây dựng nền tảng: modal 2 tab (Library + Upload), basic search, delete. GĐ14.5 mở rộng theo
mô hình my-builder (project landing page của Sonth, đã audit trực tiếp code thật —
`packages/builder-editor/src/panels/MediaManager.tsx`, `apps/api/src/routes/media.routes.ts`).

**Đối chiếu thực tế my-builder (KHÔNG suy đoán, đọc code):**
- 3 tab: Library / Upload / URL — filter type CHỈ 3 nút (All/Image/Video), KHÔNG dropdown 5 loại.
- Search chỉ match `name`/`id`, client-side `useMemo`, KHÔNG pagination (danh sách nhỏ, chấp
  nhận render hết).
- `tags?: string[]` CÓ trong type `Asset` nhưng KHÔNG bao giờ được dùng để filter ở UI thật —
  field tồn tại nhưng chưa có consumer. KHÔNG bịa thêm UI filter theo tag ở đây.
- **URL tab của my-builder KHÔNG tải file về, KHÔNG persist vào asset list** — chỉ tạo 1 object
  `Asset` tạm client-side từ chuỗi URL (`id: url`, `source: 'url'`), gọi `onSelect` NGAY (áp dụng
  + đóng dialog). Vì my-builder là web app, giả định luôn có mạng — ảnh tham chiếu URL ngoài vẫn
  hiển thị được mỗi lần load trang.

**Vì sao sky-app KHÔNG thể copy nguyên URL tab của my-builder:**
`CLAUDE.md`'s nguyên tắc **"Isomorphic + offline-first: chạy cả Web lẫn Electron, không phụ thuộc
mạng bắt buộc"** — nếu `ImageItem.src` trỏ thẳng 1 URL ngoài (VD Unsplash), layout SẼ VỠ khi trình
chiếu ceremony ở nơi không có Internet (khả năng thực tế cao — LED tại hội trường/sân trường).
Do đó URL tab ở sky-app **PHẢI tải file về lưu local NGAY khi thêm** (khác my-builder), biến URL
paste thành 1 asset cục bộ bình thường — điểm khác biệt CÓ CHỦ ĐÍCH, không phải hiểu sai plan gốc.

GĐ14.5 gồm:
- **URL tab** — paste link, tải về + lưu local ngay (không pass-through như my-builder)
- **Type auto-detection** — `.mp4`→video, `.ttf`→font, `.jpg`→image tự động (giống my-builder)
- **Type filter đơn giản** — All/Image/Video/Font/File (my-builder chỉ All/Image/Video vì không
  cần font/file cho landing page; sky-app cần đủ 5 loại vì Media Library dùng chung cho asset
  Frame ảnh + tương lai có thể mở rộng font tuỳ chỉnh)
- **Rich metadata** — asset type, dimensions, MIME type, upload timestamp (giống my-builder)
- **Pagination + tag filter UI** — KHÔNG có trong my-builder, hạ xuống mục riêng "Mở rộng
  KHÔNG theo my-builder" bên dưới, tự quyết định làm hay không riêng, không tính vào scope chính
  của GĐ14.5.
- **AssetProvider interface** — extensible cho AWS S3, Cloudinary, custom backends (backlog, để sau)

## Mở rộng types — `AssetMeta` → `Asset`

```ts
// packages/service-contracts/src/asset.ts — thay `AssetMeta` bằng `Asset` đầy đủ hơn
export type AssetType = 'image' | 'video' | 'font' | 'file' | 'icon';

export interface Asset {
  id: string;
  type: AssetType;
  name: string;
  url: string; // Resolved URL (HTTP or data:// for WASM)
  thumbnailUrl?: string; // Separate thumbnail, size-optimized
  size?: number; // Bytes
  dimensions?: { width: number; height: number }; // px, for images/video only
  mimeType?: string; // 'image/png', 'video/mp4', etc.
  uploadedAt?: string; // ISO 8601
  tags?: string[]; // Searchable labels
  source: 'local' | 'url' | string; // 'local' = uploaded, 'url' = pasted URL, or provider ID
}

export interface AssetQuery {
  type?: AssetType; // Filter
  search?: string; // By name/tags
  tags?: string[]; // Filter by tags
  page?: number;
  pageSize?: number; // Default 20
}

export interface AssetListResult {
  assets: Asset[];
  total: number; // For pagination UI
  page: number;
  pageSize: number;
}

// Thay `AssetPort.listAssets()` trả `AssetMeta[]` bằng:
export interface AssetPort {
  // ... pickAndSaveImage, resolveAssetUrl, deleteAsset như cũ ...
  saveImageBlob?(file: Blob, filename: string): Promise<{ relativePath: string }>;

  // MỚI — query assets (replace listAssets từ GĐ14). KHÔNG bắt buộc hỗ trợ pagination thật ở v1
  // (page/pageSize CÓ trong signature để tương lai mở rộng, nhưng adapter có thể trả HẾT 1 lần
  // rồi FE tự paginate client-side — xem "Mở rộng KHÔNG theo my-builder" bên dưới).
  queryAssets?(query: AssetQuery): Promise<AssetListResult>;

  // MỚI — thêm asset từ URL ngoài. KHÁC my-builder: bắt buộc TẢI VỀ + LƯU LOCAL ngay (không
  // pass-through URL) vì sky-app phải chạy offline-first (xem giải thích ở Bối cảnh). Trả về
  // Asset đã lưu — `url`/`thumbnailUrl` field của kết quả LÀ local resolved URL, không phải URL
  // gốc user paste.
  addAssetFromUrl?(url: string): Promise<Asset>;
}
```

Các adapter 3 platform cập nhật `listAssets()` → `queryAssets()`. Pagination CHỈ implement khi có
nhu cầu thật (thư viện thực tế vượt ~50-100 ảnh và danh sách render chậm) — v1 mặc định trả toàn
bộ (giống my-builder KHÔNG hề paginate), field `page`/`pageSize`/`total` trong `AssetListResult`
tồn tại nhưng adapter có thể luôn trả `page:1, pageSize: assets.length, total: assets.length`.

// packages/platform-web/src/adapters/asset.ts
async queryAssets(query: AssetQuery): Promise<AssetListResult> {
  const params = new URLSearchParams();
  if (query.type) params.append('type', query.type);
  if (query.search) params.append('search', query.search);
  if (query.tags?.length) params.append('tags', query.tags.join(','));
  params.append('page', String(query.page ?? 1));
  params.append('pageSize', String(query.pageSize ?? 20));
  
  const res = await fetch(`/api/layout-assets?${params}`);
  return res.json();
}

async addAssetFromUrl(url: string): Promise<Asset> {
  const res = await fetch('/api/layout-assets/from-url', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ url }),
  });
  return res.json();
}

### WASM adapter

```ts
// packages/platform-web/src/adapters/wasm-asset.ts
async queryAssets(query: AssetQuery): Promise<AssetListResult> {
  const db = await getDb();
  return new Promise((resolve) => {
    const tx = db.transaction(storeName, 'readonly');
    const store = tx.objectStore(storeName);
    const allAssets: Asset[] = [];
    
    const req = store.getAll();
    req.onsuccess = () => {
      let filtered = req.result as Asset[];
      
      // Filter by type
      if (query.type) filtered = filtered.filter((a) => a.type === query.type);
      
      // Filter by tags
      if (query.tags?.length) {
        filtered = filtered.filter((a) => query.tags?.some((tag) => a.tags?.includes(tag)));
      }
      
      // Search by name
      if (query.search) {
        const q = query.search.toLowerCase();
        filtered = filtered.filter((a) => a.name.toLowerCase().includes(q));
      }
      
      // Sort by uploadedAt desc
      filtered.sort((a, b) => new Date(b.uploadedAt!).getTime() - new Date(a.uploadedAt!).getTime());
      
      // Paginate
      const page = query.page ?? 1;
      const pageSize = query.pageSize ?? 20;
      const start = (page - 1) * pageSize;
      const end = start + pageSize;
      
      resolve({
        assets: filtered.slice(start, end),
        total: filtered.length,
        page,
        pageSize,
      });
    };
  });
}

async addAssetFromUrl(url: string): Promise<Asset> {
  const type = detectAssetType(url);
  const res = await fetch(url); // Cần mạng NGAY LÚC NÀY — không cần mạng lúc trình chiếu sau đó
  if (!res.ok) throw new Error(`Không tải được URL: ${res.status}`);
  const blob = await res.blob();

  const id = `asset_${Date.now()}_${Math.random().toString(36).slice(2)}`;
  const blobKey = `blob_${id}`;

  // Lưu blob THẬT vào asset-blob-store (KHÔNG lưu url gốc làm nguồn hiển thị — nếu không, asset
  // này sẽ vỡ offline giống my-builder's URL tab, đúng lỗi cần tránh đã nêu ở Bối cảnh).
  await saveAssetBlob(blobKey, blob); // hàm đã có sẵn từ GĐ14 (asset-blob-store.ts)

  let dimensions: { width: number; height: number } | undefined;
  if (type === 'image') {
    dimensions = await new Promise((resolve) => {
      const img = new Image();
      img.onload = () => resolve({ width: img.width, height: img.height });
      img.onerror = () => resolve(undefined as any);
      img.src = URL.createObjectURL(blob);
    });
  }

  const asset: Asset = {
    id,
    type,
    name: url.split('/').pop() || url,
    url: blobKey, // "key blob" cục bộ — resolve qua resolveAssetUrl như mọi asset WASM khác,
                  // KHÔNG phải url gốc user paste (xem AssetPort's comment gốc về sự khác biệt
                  // relativePath/key-blob vs URL hiển thị được).
    size: blob.size,
    mimeType: blob.type,
    dimensions,
    uploadedAt: new Date().toISOString(),
    source: 'url',
  };

  const db = await getDb();
  return new Promise((resolve, reject) => {
    const tx = db.transaction(storeName, 'readwrite');
    const store = tx.objectStore(storeName);
    const req = store.put(asset);
    req.onerror = () => reject(req.error);
    req.onsuccess = () => resolve(asset);
  });
}

function detectAssetType(url: string): AssetType {
  const ext = url.split('.').pop()?.toLowerCase() || '';
  if (['jpg', 'jpeg', 'png', 'gif', 'webp', 'svg'].includes(ext)) return 'image';
  if (['mp4', 'webm', 'mov', 'avi'].includes(ext)) return 'video';
  if (['ttf', 'otf', 'woff', 'woff2'].includes(ext)) return 'font';
  return 'file';
}
```

## Vấn đề phát sinh & cách xử lý

- **Dimensions detection for images:**
  - Web: fetch image → new Image() → img.onload đọc width/height
  - Electron: nhận ArrayBuffer, dùng jimp hoặc sizeOf library để đọc dimensions
  - WASM: client-side qua new Image()

- **Type auto-detection cho URL:**
  - Dùng file extension từ URL pathname
  - Fallback dùng response Content-Type header (Web/Electron)
  - WASM: client-side chỉ có URL, không có network để kiểm tra header → dùng extension

- **URL tải lỗi** (URL sai/không phải ảnh/CORS chặn fetch từ trình duyệt) — hiện lỗi NGAY trong
  tab URL (`urlError` state), KHÔNG thêm vào asset list, KHÔNG throw làm crash modal. CORS là rủi
  ro THẬT với WASM (fetch từ browser bị chặn bởi CDN không set header) — Electron/Web (qua
  data-service, fetch từ server-side) KHÔNG bị giới hạn này. Ghi rõ trong UI: "Một số ảnh có thể
  không tải được do giới hạn CORS của nguồn ảnh."
